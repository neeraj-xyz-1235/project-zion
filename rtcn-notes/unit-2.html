Unit 2: Routing Fundamentals and Protocols

What routers do and how they're built, routing tables, the families of routing algorithms, and the four main protocols: RIP, OSPF, EIGRP and BGP.

1Router

A router is a specialised network device that forwards data packets between different networks, based on the destination IP address in each packet. It works at the Network Layer (Layer 3) of the OSI model.

Characteristics

  • Connects multiple distinct networks (e.g. a home network to the Internet, or offices in different cities). Switches and hubs work only inside one LAN.
  • Reads the packet header and checks its routing table to choose the next hop.
  • Picks the most efficient path for each packet.
  • Also handles fragmentation, error detection, and security such as ACLs (access control lists) and traffic filtering.

2Router vs Switch vs Hub

  • Hub (Layer 1): a repeater that broadcasts every signal to all devices, with no filtering. This causes collisions, so hubs are now obsolete.
  • Switch (Layer 2): forwards frames only to the destination device using MAC addresses. Each port is its own collision domain.
  • Router (Layer 3): routes packets between networks using IP addresses and routing protocols. It often also provides firewall, NAT and DHCP.

3Role of Routers in Networks

  • Traffic director: like a traffic police officer at each network boundary, sending every packet the right way.
  • Maintains routing tables and picks the best route using metrics such as hop count, bandwidth, delay or policy.
  • Fault tolerance: can choose new routes dynamically when a link fails.
  • Segmentation and security: isolates broadcast domains and applies traffic policies.
  • Supports VPNs and QoS (Quality of Service) in enterprises.

Example: router in a computer lab

Internet │ ISP link ISP Modem │ WAN port Router ──── File Server PC │ └─── Printer │ LAN port Lab-1 Switch ├── PC 1 └── PC 2
  • ISP modem: modulates and demodulates signals. It's the gateway to the ISP.
  • Router: its WAN port goes to the modem, and its LAN port goes to the switch. It routes between the Internet and the lab, and manages IP addresses.
  • Lab-1 switch: connects the PCs. PC-to-PC traffic stays on the switch and never reaches the router.
  • Traffic flow: inbound goes Internet → modem → router WAN → router LAN → switch → PC. Outbound is the reverse.

4Router Architecture

A router's functions are split into two parts: the Control Plane (the "brain", which decides routes) and the Data Plane (the "muscle", which moves packets).
CONTROL PLANE ┌──────────────────┐ │ Routing Processor│ runs routing protocols, │ (routing decisions)│ builds the routing table └────────┬─────────┘ │ forwarding table DATA PLANE ▼ Input ports ──▶ Switching fabric ──▶ Output ports (receive, check (internal (queue, schedule, header) highway) send out)

Data plane components

ComponentJobPost office analogy
Input portsReceive packets and check headers to make sure the data is intactWhere mail arrives
Switching fabricMoves packets from input ports to the right output ports, fastThe conveyor belt
Output portsQueue and schedule packets on the way outDelivery bins

Control plane

  • The routing processor runs routing protocols, updates routing tables, and lets administrators configure and monitor the router.
  • Analogy: the supervisor who decides which route each letter takes.

Working together: the control plane works out the best routes once. The data plane then forwards each packet quickly using that result, without deciding again every time. This split lets routers handle very high data rates.

5Routing

Routing is the process by which routers determine the path that packets take from source to destination across interconnected networks. It has two functions: path determination (finding the best route) and packet forwarding (sending the packet along it).
  • It lets devices on different networks communicate as if they were on the same network, by relaying packets through intermediate routers.
  • Small networks can use fixed paths. Large networks need routes that adapt to congestion and failures.

6How Do Routers Work?

Source device → creates packet (adds IP header) → Router → reads destination IP → consults routing table → selects best path → forwards packet → next router or destination
  1. Receive the packet: data is split into packets. Each has a source IP, destination IP, payload and other header fields.
  2. Examine the destination address in the header.
  3. Consult the routing table, which holds directly connected networks, routes learned from other routers, and metrics (cost or distance).
  4. Make a routing decision: choose the next hop, which may be a local device, another router, or the destination itself. Distance vector or link state algorithms help with this.
  5. Forward the packet out of the right interface.
  6. Handle special cases:
    • Fragmentation: split packets that are too large for the next network.
    • NAT: change private IPs to a public IP for the Internet.
    • Firewall rules: block unauthorised or harmful traffic.
  7. Reach the destination: this repeats hop by hop, and the receiver reassembles the packets.

7Routing Table

A routing table is a data structure stored in a router that lists destination networks and how to reach them. The router uses it to choose the next hop for every packet. It can be built manually (static) or by routing protocols (dynamic).

Example lookup: packet to 192.168.2.45

  1. Extract the destination IP 192.168.2.45.
  2. Find the longest prefix match: 192.168.2.0/24.
  3. Next hop = 192.168.20.1.
  4. Forward out of Gi0/1.

This is called IP forwarding or route lookup. 0.0.0.0/0 is the default route, used when nothing else matches.

Longest prefix match: if several entries match, the one with the longest prefix (the most specific route) wins.

9Routing Algorithms

Routing algorithms are techniques for finding the best path for packets from source to destination, by criteria such as shortest distance, lowest cost or minimum delay. They are the basis of routing protocols.

Key concepts

  • Path: the sequence of nodes a packet passes through.
  • Metric: the value used to judge the best path (distance, cost, delay).
  • Convergence: the state when all routers have consistent routing information.

Types

Routing algorithms ├── Static (manual) └── Dynamic (adaptive) ├── Distance Vector → RIP ├── Link State → OSPF ├── Path Vector → BGP └── Hybrid → EIGRP Others: Flooding, Hierarchical routing

a) Distance vector routing

  • Each router keeps a table of distances to every destination.
  • It shares its table only with immediate neighbours, periodically.
  • It picks the route with the smallest distance (Bellman-Ford).
  • Example: RIP. Simple, but converges slowly and can form loops (count-to-infinity).

b) Link state routing

  • Each router keeps a complete map (topology) of the network.
  • It shares link state information with all routers (flooding).
  • Computes routes with Dijkstra's shortest path algorithm.
  • Example: OSPF. Converges fast and is reliable, but needs more memory and CPU.

c) Path vector routing

  • Keeps the full path (the list of ASes) to each destination, so loops can be spotted and avoided.
  • Used between autonomous systems (inter-domain).
  • Example: BGP. Scalable and loop-free, but complex and slower to update.

Other types

  • Flooding: sends each packet out of every link except the one it came in on. Simple and guarantees delivery, but very redundant and causes congestion.
  • Hierarchical routing: divides the network into regions or levels, which cuts routing table size and complexity.
  • Hybrid routing: combines distance vector and link state. Example: EIGRP.

10Routing Protocols

Routing protocols are the rules routers use to dynamically discover destinations and exchange routing information, so they can pick the best, loop-free path.

Categories

  • By algorithm: distance vector, link state, hybrid (and path vector).
  • By scope:
    • IGP (Interior Gateway Protocol): routing inside one autonomous system (AS). Examples: RIP, OSPF, EIGRP.
    • EGP (Exterior Gateway Protocol): routing between ASes. Example: BGP.

An Autonomous System (AS) is a group of networks and routers under one administration, such as one ISP or a large company.

11Routing Information Protocol (RIP)

RIP is one of the earliest and simplest distance vector routing protocols. It uses hop count as its metric to find the shortest path, and is based on the Bellman-Ford algorithm.

Key features

FeatureValue
TypeDistance vector (IGP)
MetricHop count
Maximum hops15 (16 = unreachable, "infinity")
Update intervalEvery 30 seconds, with the whole table
TransportUDP port 520
AlgorithmBellman-Ford

Working steps

  1. Each router starts with its directly connected networks (hop count 0).
  2. Every 30 s, each router sends its whole routing table to its neighbours.
  3. When a router receives a neighbour's table, it adds 1 to every hop count, compares with its own entries, and keeps the shorter path.
  4. This repeats until all tables are consistent (convergence).
  5. An unreachable route is marked with hop count 16.

Example

Net A ── R1 ── R2 ── R3 ── Net C │ R4 ── Net D

Step 1 (initial): each router knows only its own network. R1: Net A, direct, 0.

Step 2 (exchange): R1, R3 and R4 send their tables to R2. R2 learns Net A via R1 (1), Net C via R3 (1) and Net D via R4 (1).

Step 3 (propagation): R2 advertises to everyone. R1 learns Net C and Net D via R2 (2 hops). R3 and R4 likewise.

Variants

  • RIP v1: classful, with no subnet masks. Updates are broadcast.
  • RIP v2: classless (supports CIDR and VLSM) and supports authentication. Updates are multicast to 224.0.0.9.
  • RIPng: RIP for IPv6.

Advantages

  • Simple to configure and manage
  • Suitable for small networks
  • Updates routes automatically

Limitations

  • 15-hop limit restricts network size
  • Slow convergence (periodic updates)
  • Routing loops and count-to-infinity
  • Inefficient for large or dynamic networks

Applications: small enterprise networks, teaching labs, early-stage LANs where simplicity matters more than scale.

12Open Shortest Path First (OSPF)

OSPF is a link state routing protocol that builds a full map of the network and uses Dijkstra's shortest path algorithm. It is designed for large, hierarchical networks and supports VLSM and CIDR.

Working principle

  1. Each router collects information about its directly connected links and neighbours.
  2. It builds Link State Advertisements (LSAs) describing those links.
  3. It floods LSAs to every router in the area.
  4. Each router runs Dijkstra on the complete map to find the shortest path to every destination.

Areas

┌──────── Area 0 (backbone) ────────┐ │ R1 ─────── R2 ─────── R3 │ └──────────────┼────────────────────┘ │ R2 = Area Border Router (ABR) ┌──────────────┼───── Area 1 ───────┐ │ R4 │ └───────────────────────────────────┘
  • Routers are grouped into areas to reduce routing overhead. LSAs are flooded only within an area.
  • Area 0 is the backbone, and all other areas must connect to it.
  • An Area Border Router (ABR) connects an area to the backbone.

Features

  • Dijkstra's shortest path algorithm.
  • Hierarchical design through areas.
  • Metric = cost, based on bandwidth.
  • Fast convergence through LSA flooding.
  • Supports authentication and CIDR.

Advantages

  • Efficient for large, complex networks
  • Rapid convergence
  • No routing loops
  • Load balancing

Limitations

  • More complex to configure than RIP
  • High memory and CPU use

Applications: large enterprise and service-provider networks, campus and multi-area networks.

13Enhanced Interior Gateway Routing Protocol (EIGRP)

EIGRP is a hybrid routing protocol developed by Cisco. It combines features of distance vector and link state protocols, and uses DUAL (Diffusing Update Algorithm) for fast, loop-free routing.

Three tables

TableContents
Neighbor tableDirectly connected EIGRP routers
Topology tableAll learned routes with their metrics
Routing tableThe best paths chosen from the topology table
  • Sends partial, incremental updates only when something changes, which saves bandwidth.
  • DUAL keeps a backup route (the feasible successor) ready, so failover is almost instant.

Metric

Composite metric = f(Bandwidth, Delay, Reliability, Load). Bandwidth and delay are the main factors.

Advantages

  • Converges faster than RIP and OSPF
  • Supports VLSM and CIDR
  • Incremental updates
  • Loop-free through DUAL

Limitations

  • Cisco-proprietary (later partly opened)
  • More complex metric calculation

Applications: Cisco-based enterprise networks; medium to large organisations that need stability.

14Border Gateway Protocol (BGP)

BGP is the path vector routing protocol used to exchange routing information between Autonomous Systems (ASes). It is the protocol that runs the global Internet.

Working principle

  • Each BGP router (a BGP speaker) keeps a table of networks and the paths to reach them.
  • It uses policy-based routing on path attributes rather than simple metrics like hop count.
  • iBGP (internal BGP): between routers in the same AS.
  • eBGP (external BGP): between routers in different ASes.
  • It exchanges reachability information, not the full topology. It runs over TCP port 179.not in slides

  • Scalable and reliable for inter-domain routing

  • Slower convergence than OSPF or EIGRP
  • Complex to configure and maintain

Evolution

  • RIP brought simplicity and basic route discovery.
  • OSPF brought scalability and structure (link state, areas).
  • EIGRP brought rapid convergence and smarter metrics.
  • BGP made global, policy-based Internet routing possible.

Applications of routing

  • Internet backbone: delivering packets across the globe.
  • Enterprise networks: connecting branches and data centres.
  • Wireless networks: supporting mobile users and changing topologies.
  • Traffic engineering: managing resources for performance.
One-liners: RIP = hops, max 15, every 30 s · OSPF = Dijkstra, areas, cost · EIGRP = Cisco, DUAL, 3 tables · BGP = between ASes, AS path, the Internet.
