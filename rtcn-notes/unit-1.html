Unit 1: Internet, IP and Addressing

How the Internet is structured, who runs it, the IPv4 and IPv6 headers, subnetting and supernetting, and how ARP and RARP map addresses.

1Network, Computer Network & Internet

A network is a collection of two or more devices connected by communication links to share data and resources.
A computer network is a collection of autonomous, interconnected computers and devices that share resources and exchange data.
The Internet is a global network connecting millions of computers and devices worldwide so they can communicate and share information. Example: browsing Google or watching YouTube.
internet vs Internet: an internet (small i) is any two or more networks that can talk to each other. The Internet (capital I) is the one worldwide internet made of thousands of interconnected networks.

2Structure of the Internet

The Internet has a three-level hierarchy: backbone networks at the top, provider networks in the middle and customer networks at the edge.

3Role of the Internet Service Provider (ISP)

An ISP is an organisation that supplies Internet access to individuals and businesses. It is the bridge between the user's device and the Internet backbone. Without ISPs, end users would have no way to reach the Internet.

Functions of an ISP

FunctionDescription
Internet connectivityProvides broadband, fibre-optic or wireless connections.
IP address allocationAssigns each device a unique IP address, dynamically or statically.
DNS serviceRuns DNS servers that convert domain names into IP addresses.
Email and hostingMany ISPs offer web hosting and email.
Network managementMaintains routers, switches and servers for uninterrupted connectivity.

How a request reaches a website

User device → Modem / Router → ISP → Internet backbone (gateway routers) → Web server / cloud (PC, phone) (converts signal, (gives IP, DNS, (high-speed routes (Google, YouTube, shares via Wi-Fi) routes traffic) between ISPs) Amazon)
  • Modem converts local digital data into signals for phone lines, fibre or cable. The router shares the connection over Wi-Fi or Ethernet.
  • The ISP gives an IP address, connects the local network to the Internet, manages DNS, routes data and handles bandwidth.
  • The backbone connects ISPs across countries and continents.

Types of ISP connection

DSL · Wi-Fi broadband · Mobile broadband · Fibre-optic broadband · Cable broadband

Examples

Reliance Jio, Vodafone Idea, Airtel, BSNL, Hathway, ACT

Advantages

  • Customer doesn't handle the technical or financial side of connectivity
  • High-speed Internet
  • High reliability and availability
  • Security: protection against viruses, up-to-date patches
  • No need to run your own web server
  • Uptime guarantees

Disadvantages

  • Some ISPs inflate prices or lose data. The customer depends fully on the ISP.
  • Overloaded shared servers cause slow speeds
  • You must trust the ISP for uptime and security
  • If the ISP gets blacklisted, the user is affected

ISP-related applications

Router management apps · data usage apps · speed test apps · customer support apps · billing apps

4Intranet

An intranet is a private network used within an organisation to securely share information, resources and services among its employees.

Uses

  • Collaboration: easier sharing of information so employees can work together.
  • Communication: employee directories, company news and organisation charts.
  • Easy access to information: policies, benefits and updates.
  • Automation: automates repeatable everyday tasks.

How an intranet works

  • A web server handles requests for data and delivers files to users. A content management system controls the content.
  • It may be many interlinked LANs plus leased lines to WAN resources. It uses TCP/IP and HTTP, like the Internet.
  • Employees need a network password and a connection to the company LAN. Remote employees use a VPN.
  • A firewall sits between the Internet and the intranet. It checks all packets and blocks unauthorised requests and malware.
Employees ── LAN ── Web server + CMS ── Firewall ── Internet ▲ Remote employee ─────── VPN ────────────────┘

Advantages

  • Better communication, information sharing and collaboration
  • Simpler records management
  • Streamlined tracking of requests
  • A test environment for ideas before they go on the public website
  • A better corporate culture
  • Good return on investment (low cost)

Disadvantages

  • Low participation means too little content
  • High staff cost leads to poor support
  • Needs regular maintenance and inspection
  • Unclear ownership complicates management
  • Weak mobile and remote support

5Role of ICANN

ICANN (Internet Corporation for Assigned Names and Numbers) is a global non-profit organisation founded in 1998 that coordinates the databases for the Internet's names (domains) and numbers (IP addresses).

Functions

FunctionDescription
DNS managementOversees top-level domains such as .com, .org, .in and .edu.
IP address allocationAllocates IP address blocks to Regional Internet Registries (APNIC, ARIN, RIPE NCC).
Registrar accreditationAuthorises companies such as GoDaddy and Namecheap to sell domain names.
Global coordinationMakes sure each domain name and IP address stays unique and globally resolvable.
ICANN ──▶ Regional registries (APNIC, ARIN, RIPE NCC) ──▶ ISPs ──▶ Users (IP addresses) ICANN ──▶ Accredited registrars (GoDaddy, Namecheap) ──▶ Domain owners (domain names)

Example

When someone registers www.cwit.edu, ICANN's system makes sure it maps to a unique IP address and is routed correctly, so there are no duplicate or conflicting names.

Importance

Without ICANN there would be chaos: overlapping addresses, duplicate domain names and unreliable access to websites.

6Internet Protocol (IP)

IP is an unreliable, connectionless datagram protocol that gives a best-effort delivery service. It does its best to deliver each packet but gives no guarantee, and does no error checking or tracking.

Characteristics

  • Best effort: no error checking or tracking. If reliability matters, IP is paired with TCP.
  • Connectionless: no call setup and no virtual circuits. Each datagram is sent separately.
  • Datagrams can take different routes, and can arrive out of order or duplicated. IP doesn't reorder them.
  • This limited functionality is a strength: applications add only the reliability they need, which keeps things efficient.

Post office analogy

  • IP is like ordinary post. The post office tries to deliver the letter, but if it's lost, nobody tells the sender.
  • IP + TCP is like adding a self-addressed postcard. The receiver mails it back to confirm delivery. If it never comes back, the sender sends another copy.

7IPv4 Datagram Header Format

An IP datagram is a variable-length packet with a header and data. The header is 20 to 60 bytes and holds the information needed for routing and delivery.
0 4 8 16 19 31 ┌────────┬────────┬───────────────┬───────────────────────────────┐ │Version │ HLEN │ Service type │ Total length │ ├────────┴────────┴───────────────┼───────┬───────────────────────┤ │ Identification │ Flags │ Fragmentation offset │ ├─────────────────┬───────────────┼───────┴───────────────────────┤ │ Time to live │ Protocol │ Header checksum │ ├─────────────────┴───────────────┴───────────────────────────────┤ │ Source IP address (32) │ ├─────────────────────────────────────────────────────────────────┤ │ Destination IP address (32) │ ├─────────────────────────────────────────────────────────────────┤ │ Options (0 – 40 bytes) │ └─────────────────────────────────────────────────────────────────┘
Field (bits)Purpose
Version (4)IP version. For IPv4 it is 0100 (4).
HLEN (4)Header length in 4-byte words. Max 15 × 4 = 60 bytes.
Service type (8)How to handle the datagram: priority, and the throughput, reliability and delay wanted.
Total length (16)Length of the whole datagram (header + data), up to 65,535 bytes.
Identification (16)Used in fragmentation. All fragments of one datagram carry the same number.
Flags (3)Fragmentation control: may it be fragmented, and is this the last fragment?
Fragmentation offset (13)Position of this fragment's data in the original datagram.
Time to live (8)Maximum number of hops. Each router subtracts 1, and at 0 the datagram is discarded. This stops packets looping forever.
Protocol (8)The upper-layer protocol inside (e.g. TCP = 6, UDP = 17).
Header checksum (16)Checks the integrity of the header only, not the data.
Source address (32)IP address of the original sender.
Destination address (32)IP address of the final receiver.
Options (variable)Extra functions: routing, timing, management, alignment.
Remember: header = 20 bytes minimum, 60 maximum. TTL counts hops, not seconds, in practice. The checksum covers the header only.

8IPv4 Addressing

IPv4 (Internet Protocol version 4) is the delivery mechanism of the TCP/IP suite. It works at the network layer and gives every device a unique 32-bit logical address.

Position in TCP/IP

Application layer │ HTTP, FTP, DNS, SMTP Transport layer │ TCP, UDP, SCTP Network layer │ IPv4 + ICMP, IGMP, ARP, RARP Data link layer │ Ethernet, Wi-Fi … Physical layer │ cables, signals

Parts of an IPv4 address

  • Network part: identifies the network (and, in classful addressing, its class).
  • Host part: identifies the machine on that network. Same network part, different host part for each device.
  • Subnet number: large networks are divided into subnets, each with its own number.

Address space

A protocol using b bits has an address space of 2b. IPv4 uses 32 bits, so 232 = 4,294,967,296 addresses (more than 4 billion).

Notations

NotationExample (same address)
Binary (base 2)10000000 00001011 00000011 00011111
Dotted-decimal (base 256)128.11.3.31. Each byte (octet) is 0–255.
Hexadecimal (base 16)0x800B031F. 8 hex digits; used in programming.

Advantages of IPv4

  • Simplicity
  • Wide compatibility
  • Mature support and development

Disadvantages of IPv4

  • Limited address space
  • Hard to scale to today's network size

9Classful Addressing

Classful addressing is the original, now obsolete, IPv4 scheme. It divides the address space into five fixed classes: A, B, C, D and E, identified by the first few bits (or the first byte in decimal).

"−2" in the host count is because the all-0s host (network address) and all-1s host (broadcast address) can't be given to devices.

Special addresses

  • 127.0.0.0 – 127.255.255.255: loopback (e.g. 127.0.0.1 = this machine).
  • 169.254.0.0 – 169.254.255.255: link-local (auto-assigned when DHCP fails).
  • 0.0.0.0 – 0.255.255.255: "this network", used within the current network.
The slide gives link-local as "169.254.0.0 – 169.254.0.16" and this-network as "0.0.0.0 – 0.0.0.8". Those are the prefix lengths (/16 and /8) written as if they were addresses. The correct ranges are shown above.

Limitations of classful addressing

  • A class A block is too large for almost any organisation, so most addresses were wasted.
  • A class B block is also too large for many organisations.
  • A class C block is too small for many organisations.
  • Class D was planned for 268 million multicast groups that never appeared, so those were wasted too.
  • Class E was reserved, and only a few addresses were used.
Quick class check: look at the first number. 0–127 A · 128–191 B · 192–223 C · 224–239 D · 240–255 E.

10IPv6

IPv6 (Internet Protocol version 6) is the successor to IPv4, designed to fix its shortcomings, mainly address exhaustion. It uses 128-bit addresses.

Features

  • 128-bit addresses instead of 32, giving a vastly larger address space.
  • Simpler, more flexible header (base header + extension headers), which speeds up routing.
  • Resource allocation support (flow label), which IPv4 lacked.
  • Room for new and future protocol options.
  • Built-in security: encryption and authentication (IPSec).
  • Fragmentation only at the source.

Address notation: hexadecimal colon

  • Divided into 8 sections, each 2 bytes (4 hex digits), separated by colons.
  • Abbreviation: leading zeros in a section can be dropped (but not trailing zeros).
  • One run of consecutive all-zero sections can be replaced with ::, once per address.not in slides
Full: FDEC:0074:0000:0000:0000:B0FF:0000:FFF0 Drop leading: FDEC:74:0:0:0:B0FF:0:FFF0 Zero compress: FDEC:74::B0FF:0:FFF0

13Classless Addressing (CIDR)

Classless addressing has no classes. Each organisation gets a block of addresses sized to its needs, with a variable-length network prefix. It was introduced to stop address depletion.
  • A household may get 2 addresses, a big organisation thousands, and an ISP hundreds of thousands.

Three rules for a block

  1. Addresses must be contiguous (one after another).
  2. The number of addresses must be a power of 2 (1, 2, 4, 8 …).
  3. The first address must be evenly divisible by the number of addresses.

Slash notation (CIDR)

The prefix length n isn't built into the address, so it's written after a slash: a.b.c.d/n. This is formally called Classless Inter-Domain Routing (CIDR), pronounced "cider".

Extracting information from an address

  1. Number of addresses: N = 232 − n
  2. First address: keep the n leftmost bits, set the rest to 0.
  3. Last address: keep the n leftmost bits, set the rest to 1.

Worked example: 167.199.170.82/27

n = 27, so N = 2^(32−27) = 2^5 = 32 addresses Last byte 82 = 010 10010 (first 3 bits belong to the prefix) First: 010 00000 = 64 → 167.199.170.64 Last: 010 11111 = 95 → 167.199.170.95

14Subnetting

Subnetting is dividing one large network into several smaller networks (subnets). Each subnet has a longer prefix than the original network.
  • Done to use addresses efficiently, manage allocation, and improve security and organisation.
  • An address is split into a network portion (which subnet) and a host portion (which device).
  • A subnet mask marks the split: a 32-bit value with 1s for the network part and 0s for the host part.

Examplenot in slides

Network 192.168.1.0/24 (256 addresses) split into 4 subnets → /26 (64 each) Subnet 1: 192.168.1.0 – 192.168.1.63 Subnet 2: 192.168.1.64 – 192.168.1.127 Subnet 3: 192.168.1.128 – 192.168.1.191 Subnet 4: 192.168.1.192 – 192.168.1.255 Mask /26 = 255.255.255.192

Advantages

  1. Efficient IP use: less wastage.
  2. Better performance: broadcast traffic stays inside each subnet.
  3. Better security: parts of the network are isolated.
  4. Flexible and scalable: add subnets without changing the whole scheme.
  5. Simpler management: smaller segments are easier to troubleshoot.

15Address Masking

An address mask is a 32-bit number with the n leftmost bits set to 1 and the remaining (32 − n) bits set to 0. A program uses it with bitwise NOT, AND and OR to get information about a block.

Formulas

  1. Number of addresses: N = NOT(mask) + 1
  2. First address: (any address in the block) AND (mask)
  3. Last address: (any address in the block) OR (NOT mask)

Example: 167.199.170.82/27

Mask (/27) = 255.255.255.224 NOT mask = 0.0.0.31 N = 0.0.0.31 + 1 = 32 addresses First = 167.199.170.82 AND 255.255.255.224 = 167.199.170.64 Last = 167.199.170.82 OR 0.0.0.31 = 167.199.170.95
The slide's version of this example has errors: it writes the mask as "256.256.256.224" (it's 255.255.255.224), and gives first = .82 and last = .255. The correct answers are .64 and .95, as worked out above and in topic 13.

16Supernetting

Supernetting is the opposite of subnetting: it combines several smaller contiguous networks into one larger network (supernet). This is also called route summarisation or aggregation.

Benefits

  • Saves space in routing tables.
  • Reduces the number of routing updates.
  • Simplifies routing decisions.
  • Controls routing-table growth as the Internet expands.

Rules

  • All networks must be contiguous.
  • All blocks must be the same size, and the count must be a power of 2.
  • The first network ID must be divisible by the total size of the supernet.

Examplenot in slides

200.1.0.0/24, 200.1.1.0/24, 200.1.2.0/24, 200.1.3.0/24 (4 contiguous /24s) ↓ combine (4 = 2^2, so the prefix shrinks by 2) 200.1.0.0/22 → one routing entry instead of four

17Address Resolution Protocol (ARP)

ARP maps a logical (IP) address to a physical (MAC) address. It is used to find a node's physical address when its IP address is known.

Why it's needed

  • The Internet works with IP addresses, but the data link layer (Ethernet etc.) delivers frames using MAC addresses.
  • Physical addresses have local scope and can't be changed, so a mapping is needed for every delivery on a local network.

How ARP works

1. Host A wants to send to IP 130.23.43.25 but doesn't know its MAC. 2. A BROADCASTS an ARP request: "Who has 130.23.43.25? Tell me your MAC." 3. Every host on the LAN receives it; only the owner of that IP responds. 4. The owner UNICASTS an ARP reply with its MAC address. 5. A stores the IP→MAC pair in its ARP cache and sends the datagram.
  • Request = broadcast, reply = unicast.
  • The ARP cache saves the answer, so the next packets don't need a new request.

ARP packet format

┌─────────────────────────┬─────────────────────────┐ │ Hardware type (16) │ Protocol type (16) │ ├────────────┬────────────┼─────────────────────────┤ │ HW len (8) │ PR len (8) │ Operation (16) │ ├────────────┴────────────┴─────────────────────────┤ │ Sender hardware address (6 bytes for Ethernet) │ │ Sender protocol address (4 bytes for IPv4) │ │ Target hardware address (all 0s in a request) │ │ Target protocol address │ └───────────────────────────────────────────────────┘
FieldDescription
Hardware type (16)Network type ARP is running on (Ethernet = 1).
Protocol type (16)The protocol being mapped. IPv4 = 0x0800.
Hardware length (8)Length of the physical address in bytes (Ethernet = 6).
Protocol length (8)Length of the logical address in bytes (IPv4 = 4).
Operation (16)not in slides1 = request, 2 = reply.

Encapsulation

An ARP packet is carried directly inside an Ethernet frame (not inside an IP datagram), with type field 0x0806.

18Reverse Address Resolution Protocol (RARP)

RARP finds the logical (IP) address of a machine that only knows its physical (MAC) address.

Why it's needed

  • A host normally stores its IP address on disk. But a diskless computer, or a computer joining the network for the first time, doesn't know its IP address.

How RARP works

1. Host broadcasts a RARP request containing its own MAC address. 2. Every host on the physical network receives it. 3. A RARP server recognises the request, looks up the MAC in its table, and unicasts a RARP reply containing the host's IP address.
  • Request = broadcast, reply = unicast, the same as ARP.
  • The packet format is the same as ARP, with operation 3 (request) or 4 (reply).
  • RARP has been replaced by BOOTP and then DHCP.not in slides
