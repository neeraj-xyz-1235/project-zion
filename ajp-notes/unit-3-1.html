Unit 3.1: Java Networking

Networking basics (IP, ports, protocols) and the java.net classes for talking to other machines.

Most of the class slides in this PDF (the constructor and method tables for URL, Socket, ServerSocket, DatagramSocket and InetAddress) are images and couldn't be read. Those tables are filled in from the Java API and tagged not in slides.

1Networking

Definition

Networking is the process of communication between two or more computers connected through a communication channel (the network).

Description

  • Connected computers can communicate, share files and talk to each other.
  • As the number of connected users grows, the network becomes complex, and programs must deal with that complexity.
  • Java is well suited to network programming. You can write programs that communicate with any party on the network. This is Java networking.

  • A private network is limited to peer-to-peer communication among its members. In a public network, anyone can connect and share.

3World Wide Web (WWW)

  • The WWW is a huge collection of documents (hypertext pages) spread across the Internet.
  • The Internet is often called a network of networks, since many networks are connected to each other.
  • Related terms: browsers, search engines, content, hypertext documents.

4IP Address

Definition

An IP (Internet Protocol) address is a logical address that uniquely identifies a computer on a network.

Description

  • An IPv4 address is 4 bytes (32 bits), split into 4 parts of 8 bits each. Each part ranges from 0 to 255.
  • Example: 192.168.0.1. Here 192.168.0 is the network ID and .1 is the host ID (the computer).
  • It is logical, not physical. It is assigned by the network administrator or the service provider.
The slide says the address is "segmented into 8 bytes each". It's 8 bits each (4 × 8 = 32 bits).

5Port Number & Socket Address

  • An IP address identifies a machine. A port number identifies an application running on that machine, such as a browser or mail program.
  • Port numbers range from 0 to 65535. Well-known ports include HTTP = 80, HTTPS = 443, FTP = 21 and SMTP = 25.
  • IP address + port number = socket address, which is the address of an application. Example: 10.14.90.85:27017.
The slide says "every machine is given a unique port number". Strictly, each application on a machine gets its own port. One machine has many ports.

6URL (Uniform Resource Locator)

Definition

A URL is the address of a resource (a hypertext document or file) on the Internet, e.g. https://www.example.com.

Parts of a URL

https :// nptel.ac.in : 5050 / course.php │ │ │ │ protocol server port file name (host) (optional)
  • Protocol: how to fetch the resource (http, https, ftp).
  • Host / domain name: the server the file is on.
    • www means it's on the web.
    • example is the server name.
    • .com (commercial), .org (organisation), .edu (education), and country codes such as .in India, .au Australia, .us USA, .uk United Kingdom.
  • Port: optional. If it's not given, Java's getPort() returns −1.
  • File name: the actual document, e.g. course.php.

A DNS / proxy server keeps a table that maps domain names to IP addresses.

The slide gives ".ua for USA". .ua is Ukraine, and USA is .us. It also says ".org for educational institutions". .org is for (non-profit) organisations, and .edu is for education.

7MAC Address

  • MAC (Media Access Control) address is the physical address of a machine. The IP address is the logical one.
  • It is assigned by the manufacturer and is unique for every network card.
  • It is 48 bits (6 bytes), written in hexadecimal, e.g. 00:1A:2B:3C:4D:5E.

8Socket

  • When two computers communicate, the connection is controlled by two programs, one at each end. These are called socket programs.
  • Each socket is uniquely identified by its socket address (IP + port).
  • A socket is software, not a hardware device. It is an endpoint of a two-way communication link.

11Stream Sockets vs Datagram Sockets

Java network programs come in two styles:

Stream sockets (TCP)

  • A connection is established first, then data streams continuously from one machine to the other. That's where the name comes from.
  • Connection-oriented. Uses TCP.

Datagram sockets (UDP)

  • Content is split into small parts called packets or datagrams. The size is set by the network administrator, e.g. 64 or 1024 bytes.
  • Each packet carries the sender and receiver addresses and is dropped into the network. Routers decide which way to forward it until it reaches its destination.
  • Connectionless. Uses UDP (User Datagram Protocol).

Demo: read a web page

import java.io.*;
import java.net.*;

public class URLConnectionClass {
    public static void main(String[] args) {
        try {
            URL url = new URL("https://nptel.ac.in/course.php");
            URLConnection urlcon = url.openConnection();
            InputStream stream = urlcon.getInputStream();
            int b;
            while ((b = stream.read()) != -1) {
                System.out.print((char) b);
            }
        } catch (Exception e) {
            System.out.println("Exception is " + e);
        }
    }
}

17DatagramSocket & DatagramPacket

  • DatagramSocket is a socket for sending and receiving datagram packets using UDP (connectionless).
  • DatagramPacket is the data container, one packet holding the bytes plus the destination address and port.

Methods

MethodDescription
void send(DatagramPacket p)DatagramSocket: sends a packet.
void receive(DatagramPacket p)DatagramSocket: waits for and receives a packet.
void close()DatagramSocket: closes the socket.
byte[] getData()DatagramPacket: returns the data. This is the important one for reading what arrived.
int getLength()DatagramPacket: returns the number of bytes received.

Demo: receiver (run first)

import java.net.*;

public class DReceiver {
    public static void main(String[] args) throws Exception {
        DatagramSocket ds = new DatagramSocket(3000);       // listen on port 3000
        byte[] buf = new byte[1024];
        DatagramPacket dp = new DatagramPacket(buf, 1024);
        ds.receive(dp);                                     // wait for a packet
        String str = new String(dp.getData(), 0, dp.getLength());
        System.out.println(str);
        ds.close();
    }
}

Demo: sender

import java.net.*;

public class DSender {
    public static void main(String[] args) throws Exception {
        DatagramSocket ds = new DatagramSocket();
        String str = "Welcome java";
        InetAddress ip = InetAddress.getByName("127.0.0.1");   // same machine
        DatagramPacket dp = new DatagramPacket(str.getBytes(), str.length(), ip, 3000);
        ds.send(dp);
        ds.close();
    }
}

127.0.0.1 is localhost, the default address for talking within the same machine. Sender and receiver must use the same port (3000).

20Client-Server Program (One-way)

The client sends one message, and the server receives and prints it.

  • Server: ss.accept() waits for a client request. DataInputStream reads the data.
  • Client: creates a Socket and sends with DataOutputStream.
  • The port number must be the same on both sides (6666).

MyServer.java (run first)

import java.io.*;
import java.net.*;

public class MyServer {
    public static void main(String[] args) {
        try {
            ServerSocket ss = new ServerSocket(6666);
            Socket s = ss.accept();                  // wait for a client
            DataInputStream dis = new DataInputStream(s.getInputStream());
            String str = dis.readUTF();
            System.out.println("message = " + str);
            ss.close();
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}

MyClient.java

import java.io.*;
import java.net.*;

public class MyClient {
    public static void main(String[] args) {
        try {
            Socket s = new Socket("localhost", 6666);
            DataOutputStream dout = new DataOutputStream(s.getOutputStream());
            dout.writeUTF("Hello Server");
            dout.flush();
            dout.close();
            s.close();
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}

21Client-Server Dialogue (Two-way Chat)

A dialogue: the client sends something and the server responds, then the client sends again, and so on. Both sides use DataInputStream and DataOutputStream, plus a BufferedReader to read from the keyboard. Typing "stop" ends the chat.

To talk between two different machines, use the server's real IP address in the client instead of "localhost". Nothing else changes.

Server

import java.io.*;
import java.net.*;

public class ChatServer {
    public static void main(String[] args) throws Exception {
        ServerSocket ss = new ServerSocket(3333);
        Socket s = ss.accept();
        DataInputStream din = new DataInputStream(s.getInputStream());
        DataOutputStream dout = new DataOutputStream(s.getOutputStream());
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        String str = "", reply = "";
        while (!str.equals("stop")) {
            str = din.readUTF();
            System.out.println("client says: " + str);
            reply = br.readLine();
            dout.writeUTF(reply);
            dout.flush();
        }
        s.close();
        ss.close();
    }
}

Client

import java.io.*;
import java.net.*;

public class ChatClient {
    public static void main(String[] args) throws Exception {
        Socket s = new Socket("localhost", 3333);
        DataInputStream din = new DataInputStream(s.getInputStream());
        DataOutputStream dout = new DataOutputStream(s.getOutputStream());
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        String str = "", reply = "";
        while (!str.equals("stop")) {
            str = br.readLine();
            dout.writeUTF(str);
            dout.flush();
            reply = din.readUTF();
            System.out.println("Server says: " + reply);
        }
        s.close();
    }
}

22Concurrent Server

Definition

A concurrent server can serve more than one client at the same time.

How it works

  • The server loops forever on ss.accept().
  • For each client that connects, it starts a new thread (a ClientHandler) with its own input and output streams.
  • Each thread talks to its own client, while the main thread goes straight back to accepting the next client.
  • The client program is the same as before.

Demo

import java.io.*;
import java.net.*;

public class ConcurrentServer {
    public static void main(String[] args) throws Exception {
        ServerSocket ss = new ServerSocket(5056);
        while (true) {
            Socket s = ss.accept();                       // new client
            System.out.println("Client connected: " + s);
            new ClientHandler(s).start();                 // one thread per client
        }
    }
}

class ClientHandler extends Thread {
    Socket s;
    ClientHandler(Socket s) { this.s = s; }

    public void run() {
        try {
            DataInputStream din = new DataInputStream(s.getInputStream());
            DataOutputStream dout = new DataOutputStream(s.getOutputStream());
            String msg = "";
            while (!msg.equals("stop")) {
                msg = din.readUTF();
                dout.writeUTF("Server got: " + msg);   // echo back
            }
            s.close();
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}
